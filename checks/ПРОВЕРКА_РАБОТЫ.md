# Проверка сдачи

Нужны Python 3.11+ и Pillow. Из папки `checks` установите зависимость:

```powershell
python -m pip install -r requirements.txt
```

Запуск из папки `checks`, путь к сдаче обязателен:

```powershell
python -B check_submission.py --practice 4.1 "D:\Сдача 4.1"
python -B check_submission.py --practice 4.2 "D:\Сдача 4.2"
```

Можно перетащить папку сдачи на `Проверить.bat`: он спросит `4.1` или `4.2`.
Из командной строки: `Проверить.bat "D:\Сдача 4.1" 4.1`. Второй аргумент
позволяет не вводить номер интерактивно. BAT возвращает код Python без изменения.

Коды завершения: **0** файлы прошли проверку; **1** отсутствуют файлы или неверны
данные; **2** ошибка аргументов, зависимостей или доступа к файлам. Справка:
`python -B check_submission.py --help`.

Для 4.1 нужны `До.data` или `До.raw`, `После.data` или `После.raw`, `CPU.png`,
`Вывод.txt`, `LookupExercise.cs`, `metrics.json` и шесть `before_1.csv` ...
`before_3.csv`, `after_1.csv` ... `after_3.csv`. Захваты должны быть не меньше
128 байт. Проверка не разбирает внутренний формат Unity и не подтверждает их
подлинность. Каждый CSV содержит ровно 300 строк, frame от 1 до 300,
checksum=6168064, queries=1024, valid=true, конечное elapsed_ms >=0 и медиану >0.
Итоговые медианы считаются как медианы трёх медиан запусков; ускорение равно
до/после, снижение равно `(1 - после/до) * 100`. Абсолютный допуск: 0.000001.

Создать `metrics.json` из CSV, не подменяя существующий файл:

```powershell
python -B summarize_cpu.py "D:\Сдача 4.1"
python -B summarize_cpu.py "D:\Сдача 4.1" --overwrite
```

Вторая команда явно разрешает замену. При неверном CSV старый файл сохраняется.
Коды summarizer: 0 успех; 1 неверные данные или файл уже существует;
2 аргументы или окружение.

Для 4.2 нужны `bisect.log`, `first_bad.txt`, `known_good.json`,
`reported_bad.json`, `parent.json`, `culprit.json`, `bisect.png`, `Вывод.txt`.
JSON берутся из готового теста истории, без добавления выдуманного поля commit.
Проверяются records=4096, checksum=6168064, queries=1024, budget=8192 и соответствие verdict
числу inspections: good при <=8192, bad при >8192. Ожидаются good у known_good
и parent, bad у reported_bad и culprit. Файл first_bad.txt содержит только
полный SHA из единственной итоговой строки `# first bad commit: [SHA]` в
bisect.log, а не произвольный SHA из хода поиска. Проверка не доказывает
соответствие отчётов коммитам.

PNG действительно декодируются Pillow и должны иметь размер не менее 640x360.
Это не проверка того, что на снимке нужный интерфейс или настоящие измерения.
Код, содержательность выводов и подлинность доказательств проверяет преподаватель.
