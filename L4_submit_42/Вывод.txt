С помощью git bisect найден первый плохой коммит 8ebb0ea8552a74cbe6e1996656ad335f18957678 (Use records directly in query resolution). В нём быстрый поиск по словарю был заменён на обычный цикл for по массиву records. Из-за этого для каждого запроса массив стал перебираться заново, и число обращений к данным подскочило с 5120 у родительского коммита c199b8d до 2059776 у найденного коммита, сильно превысив бюджет в 8192 обращения. Контрольная сумма правильная (6168064), но из-за перебора алгоритм стал работать неэффективно.
